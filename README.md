# Fuck Market Ads
> 应用商店去广告 LSPosed 模块，基于 `callng/NewFuckMarketAds` 进行重构与功能扩展，整体由 AI 辅助构建 / 优化。


## 项目介绍
本项目是对原版 NewFuckMarketAds 的增强版本，在保留 Hook 应用商店渲染逻辑实现去广告的核心思路之上，补齐可视化控制面板、新增大量净化规则，并修复原版长期存在的开关需要重启、子开关不生效的缺陷。

模块无联网、无后台上报，仅在目标应用商店进程内生效，目标是得到一个干净、无广告、无营销活动、可高度自定义的应用商店。

## 功能特性
### 全场景广告屏蔽
- 移除开屏广告
- 拦截切换至前台时弹出的推荐与广告
- 隐藏首页信息流、底部视频/应用推荐、热词广告
- 移除搜索建议、搜索页面、搜索结果内的推广软件
- 清除下载页、应用升级页的捆绑推荐卡片
- 净化应用详情页：屏蔽广告、引流评论、相似应用推荐
- 移除「榜单」界面广告 / 推广卡片
- 清理首页顶栏云控推广位（「看剧」「短剧」等推广 subTab，以及换马甲的新增云控位）

### 界面精简与自定义
- 屏蔽「领水果」等营销入口（隐藏 `entrance_gif` 福利动图组件）
- 隐藏多余的应用安全检测视图
- 强制启用下载超级岛（无视服务端灰度，让下载进度进入小米超级岛；可单独开关）
- 底部标签栏自定义，勾选需要保留的标签（首页 / 我的 / 视频号 / 智能体 / 应用号 / 游戏 / 榜单），其余自动隐藏
- 细节修复：正常显示非正版应用标识、处理静默推送的更新提示

### 稳定性增强
以下能力为纯保护性安全网，不受单个功能开关控制，仅由总开关统一门控：
- 防止崩溃自毁：拦截商店在连续崩溃后删除自身的机制（`PackageManagerCompat.deletePackage` 针对自身包名时阻断）
- 打破回滚死锁：让 `SelfUpdateService.isValidVersion()` 始终为真，即使商店被回滚到旧版本也能正常更新回来
- 重置崩溃计数器：hook 初始化时清空商店的异常计数（`uncaught_exception_file`），从源头消除自毁触发条件
- 配置备份与回滚恢复：自动备份商店关键 SharedPreferences，检测到配置被回滚 / 清空后自动恢复
- 全局容错：所有 hook 点均带 try‑catch，单个 hook 失败不影响其余功能

### 可视化控制面板
模块自带独立 `MainActivity` 设置页，不需要修改配置文件：
- 查看模块是否成功被 LSPosed 加载、远程偏好是否可用
- 全局总开关：一键关闭全部 Hook 逻辑
- 每一项功能提供独立开关，按需启用
- 底部导航栏提供多选列表可视化配置
- 桌面图标隐藏开关，隐藏后仅能从 LSPosed 模块列表进入设置

### 和原版的关键改进
- 运行时实时读取配置（Remote Preferences）：开关在每次 Hook 触发时读取，大部分场景无需重启应用商店即可生效。
- 原版在模块安装阶段判断开关状态，修改设置后必须重启目标应用；本版本改为运行时受控。仅少数框架、ROM 存在偏好快照缓存时，才需要重启一次应用商店。
- 榜单、活动入口采用多候选类名 + 优雅降级策略，类名不存在时静默跳过，避免闪退。

> 早期版本把子开关放在“安装期”判断，导致拨动子开关必须重启应用才生效（表现即“子开关无效”）。现已改为运行时实时受控。

## 开关生效说明
每个功能开关都会在对应 Hook 的每次调用时实时读取远程偏好：
- 在模块主页拨动任意开关后，一般无需手动重启目标应用，配置写入后实时同步，下一次相关界面加载即生效。
- 若个别 ROM、框架版本对远程偏好存在快照缓存，重启一次小米应用商店即可确保生效。
- 总开关为全局兜底，关闭后所有 Hook 在加载期直接跳过。

## 关于隐藏桌面图标
开启该选项后，模块会停用自身的 Launcher 组件，启动器将不再显示本应用图标。

恢复方式：
- 通过 LSPosed 或对应框架的模块列表打开模块主页，关闭该开关。
- 如果框架无法直接打开设置页，可在 LSPosed 内重新配置模块或重装模块恢复图标。

## 技术说明
- Hook 框架：libxposed 101.0.0 + ezXHelper
- 配置同步：libxposed 远程偏好（Remote Preferences），模块 App 侧写入，Hook 进程内读取，固定 group 为 `settings`
- 广告识别：针对应用商店组件化渲染的特点，命中组件关键字（`VideoList` / `Apps` / `ad` / `banner` / `recommend` 等）后隐藏对应容器
- 特殊页面：榜单、领水果等界面使用多候选类名方案，优雅降级，不因为类名变更直接崩溃
- 顶栏推广位清理采用“黑白名单 + 结构启发式（abNormal 特殊图标）”双判定，并在“同组存在白名单成员”时才启用默认拒绝，避免旧版本结构被误杀；永远不会把顶栏清空。
