# MiMarketPurify

> 小米应用商店净化与增强 LSPosed 模块，基于 `callng/NewFuckMarketAds` 重构与扩展。

模块无联网、无后台上报，仅在应用商店进程内生效。

## 功能

### 广告移除
- 开屏广告
- 前台切换时的广告 / 推荐
- 信息流广告（视频 / 应用推荐、热词）
- 搜索建议 / 搜索页 / 搜索结果推荐
- 升级页与下载页推荐
- 详情页广告、评论与推荐
- **榜单广告**（应用榜、游戏榜等各分类子页）
- 首页顶栏云控推广位（「看剧」「短剧」等，含换马甲的新增云控位）
- 底部标签页的数字角标与「新」字红点
- 首页搜索框左侧的云控活动入口
- 「我的」页底部推广应用列表（数据层直接返回 0 组）
- 详情页拼装推荐、底部多按钮推广栏、浏览器下载弹窗内的广告列表
- 商店弹出的「升级提醒」对话框

### 界面精简
- 应用安全检测视图
- 「领水果」活动入口
- 「我的」页拆成三个独立开关：**应用推荐**（`mine_ad_container`）、
  **官方入口**（`mine_middle_menu_container`）、**清理与卸载**
  （`phone_clear_layout` / `phone_clear_forbid_layout` / `mine_uninstall_app_layout`）。
  之所以拆开：前两个只是「不显示」，第三个隐藏后还要把同排的「应用升级」卡片
  重排成整行，副作用不同，得能单独关掉。
  卡片重排分两步：卡片自己在**横向**父容器里 `weight=1` 吃掉同排空出来的空间，
  再把 `update_icon_layout` 强制成横向 LinearLayout、把四个图标搬进去等分。
  只把 `layoutParams` 改成 `MATCH_PARENT` 是不够的——父容器是纵向时
  `weight` 不生效，四个图标会各占满一行，看着就是竖排
- 详情页「精选」
- **升级记录页推荐**（`UpdateHistoryActivity` 底部的精选推荐 / 热门下载 / 大家还安装了）
- **搜索页「也在看」**（`SearchActivityPhone` 底部的「搜索 xxx 的人也在看」）
- 底部标签栏筛选：勾选要保留的标签，其余隐藏

### 功能增强
- **强制启用下载超级岛**（无视服务端灰度，可单独开关）

### 稳定性（保护性安全网，不受单个开关控制，仅由总开关门控）
- 拦截商店连续崩溃后删除自身的自毁机制
- 打破回滚死锁、重置崩溃计数器
- 配置备份与回滚后自动恢复
- 所有 hook 点均带 try-catch，单点失败不影响其余功能

## 榜单广告是怎么判定的

榜单列表项由服务端下发，不同商店版本、不同子页的容器类与字段名都不一样，
只认一种写法必然漏。`RankAds` 采用多层递进判定：

0. **dex 扫描**：加载时枚举商店 dex，把所有 `com.xiaomi.market` 下名字含 `rank` 的类一并挂钩；
1. 挂上候选容器类 `onBindData` 的**所有重载**（参数顺序不同也不漏）；
2. 逐个尝试组件类型 getter（`getComponentType` / `getItemType` / `getBizType` …），
   按**词**匹配广告关键字——用分词而不是 `contains`，否则 `load` 会因含 "ad" 被误杀；
3. 布尔广告标记（`isAd` / `isPromote` / `isSponsored` …）为真；
4. **视图兜底**：递归隐藏类名或资源 id 命中广告关键字的子视图；
   带「广告 / 推广 / 赞助」字样角标的整条隐藏；
   头部容器（`RankHeaderView`）里接近满屏宽、宽高比 ≥ 3:1 的横幅一并隐藏；
5. **名次数字 / 名次图标**：广告项的名次图标 `iv_app_ranking` 实测为 **0x0**
   （正常项 14x39），拿不到可见的 `tv_app_ranking` 也算可疑。
   只有可疑项不超过 1/4 时才下手——榜单前三名常用另一种大卡片布局，同样没有这些 id。
   名次图标本身只做**相对**比较（明显窄于同列中位数）：实测正常值就是 14px，
   用绝对阈值会把整榜都判成广告。

> 判据 4 / 5 都要遍历列表容器，而 `onBindData` 触发时 itemView **还没挂到
> RecyclerView 上**（`parent` 为 null），容器根本找不到。
> 因此这两层都推迟到 `view.post {}` 之后再扫——这一步没做的话，
> 前面所有判据都在空转，广告项连被判定的机会都没有。

第 5 层带**安全阀**：命中过多就整轮放弃并记日志，宁可放过也不清空整榜。

> 别把 Fragment 当 bean：`onBindData` 会把宿主 Fragment 一起传进来，
> 挑中它的话十几个类型 getter 全打在 Fragment 上，永远返回 null
> （日志表现为 `<- RankTabFragment type=<none>`）。排除掉之后才能拿到真正的 bean
> （`AppInfoNative`，类型 `nativeRankListApps`）。

### 榜单还有广告时怎么确认

1. 主页 → **模块自身** 二级页，打开 **「榜单调试提示」**（用完关掉）；
2. 彻底**重启应用商店**，进「榜单 → 游戏榜」上下滚一屏；
3. 抓 `adb logcat -s MiMarketPurify:W *:S`，把 `[rank]` / `[rank-tree]` 开头的行发出来：
   - `[rank] 容器类 <- bean 类 type=组件类型` —— bean 层信息；
   - `[rank] 名次宽度 … px / 无名次 N 项 / 共 M 项` —— 用于校准第 5 层判据；
   - `[rank-tree] 类名#资源名 宽x高 "文本"` —— 完整视图树（含 TextView 的文本），
     广告角标通常是那个**比同排其它标签宽得多**的 TextView，看一眼就知道该匹配什么。

> 日志级别用 WARN 而不是 DEBUG：多数框架和日志 App 会过滤 DEBUG，等于白打。
> 启动时还会输出 `移除榜单广告: 已挂载 N 个绑定点`，N 为 0 表示候选类全部落空。

## 界面设计

所有界面均为**原生 View 手写**，视觉参照 HyperOS / MiuiX，不引入任何 UI 框架：

- **分组卡片**：同一分组的开关放进一整块白底圆角容器，**组内不画分隔线**，只用少量留白分行；
- **强调色** `#0A84FF`（开关开启态、链接、胶囊按钮），关闭态轨道 `#D1D1D6`；
- **开关自绘**：系统默认滑块比轨道高、会戳出轨道外，这里用 28dp 胶囊轨道包住 24dp 白滑块；
- **圆角 ripple**：按压反馈用与卡片同圆角的 mask，系统默认矩形高亮会从圆角处溢出成方角；
- **整行可点**：点标题或空白处即可翻转开关，触摸目标不小于 48dp；
- **状态表达**：模块是否可用由顶部状态卡说明（激活绿 / 未激活橙），不靠调暗控件；
  总开关关闭时功能行整行转灰且不可点；
- 关于页返回键是 48dp 圆形图标按钮，而不是纤细的文本符号。

## 主页与开关

- 标题颜色即激活状态灯（绿 = 已激活），内容区顶部另有状态卡说明原因与处理方式；
- 固定顶栏 + 内容区滚动；右上角「关于」进入关于页，**点击关于页顶部应用卡片可跳转源码仓库**；
- **主页只留高频开关**，其余按「同一个页面」或「带子选项」收进二级页。
  此前主页近二十行开关要反复滚动才能看全，而其中大半属于「我的」页 / 底部标签栏
  这类平时很少动的局部设置：

| 位置 | 内容 |
| --- | --- |
| 主页 · 广告移除 | 开屏、前台广告/推荐、信息流、搜索、升级/下载、详情页、榜单 |
| 主页 · 功能增强 | 下载超级岛、细节修正 |
| 二级 ·「我的」页 | 应用推荐、官方入口、清理与卸载 |
| 二级 · 底部标签栏 | 启用筛选 + 「保留哪些标签」多选 |
| 二级 · 其他界面净化 | 应用安全检测、领水果入口、详情页「精选」、升级记录页推荐、搜索页「也在看」 |
| 二级 · 模块自身 | 隐藏桌面图标、榜单调试提示 |

- 二级页入口行右侧显示当前状态（「已启用 2/3」「已隐藏 2 个」等），
  摘要是**求值函数**而不是固定字符串，从二级页返回主屏时自动重算；
- 「保留哪些标签」的多选紧跟在启用筛选开关下面、同属一张卡片，开关关闭时整体隐藏；
- 主页与所有二级页共用 `SettingsBaseActivity`：同一套骨架（固定顶栏 + 滚动内容区）、
  同一套开关行、同一套远程偏好读写与总开关门控——四种二级页共用一个 Activity，
  差异只在数据，写四遍只会让样式悄悄分叉；
- 界面适配 edge-to-edge，系统栏 insets 分别回填到固定顶栏顶部与内容区底部；

### 开关何时生效
开关在 hook 每次调用时实时读取远程偏好，一般**无需重启**；个别 ROM 缓存了快照时，
重启一次应用商店即可。总开关关闭后所有 hook 直接跳过。

### 隐藏桌面图标
只停用桌面入口的 activity-alias（`.LauncherAlias`），`MainActivity` 始终保持启用，
因此框架的模块列表仍可打开主页。此前被旧版本锁出的设备，覆盖安装时会自动恢复入口。

## 技术说明
- Hook 框架：libxposed 101.0.0 + ezXHelper
- 主页 UI：原生 View 手写，零 UI 框架依赖（不依赖 Compose / AppCompat / Material）
- 分支：[`miuix`](https://github.com/moonbai/MiMarketPurify/tree/miuix) 曾用 Compose + MiuiX 重写主页，
  因体积原因未并入主线
- 构建：AGP 9.1.0 + JDK 21，`compileSdk 36` / `minSdk 29`
- 配置同步：libxposed 远程偏好，模块侧写入、hook 侧读取，固定 group 为 `settings`
- 界面元素屏蔽：不写死「第几层第几个子 View」，改用**资源 id** 与**角标文案**做锚点；
  `View.onAttachedToWindow` 全量拦截 + 主界面 / 详情页 `onResume` 整树补扫双路径生效
